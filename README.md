# Data Structures and Algorithms in Python

A growing collection of my **Data Structures and Algorithms (DSA) practice**, with solutions to coding problems written primarily in Python.

This repository is more than a collection of accepted submissions. It is a place to practise problem-solving, understand algorithmic patterns, compare approaches, and prepare for coding interviews.

## Goals

- Build a strong foundation in data structures and algorithms.
- Develop clear, readable, and maintainable solutions.
- Learn to improve a straightforward solution through algorithmic reasoning.
- Understand time and auxiliary-space complexity.
- Keep my practice organized so solutions are easy to revisit and revise.

## What you'll find here

Solutions and supporting notes are organized into problem-specific folders. Depending on the problem, a folder may contain one or more Python implementations and a README explaining the approach, examples, or complexity analysis.

The collection will grow as I solve and review more problems. The repository is intentionally not tied to a fixed problem list or directory snapshot, so new topics and solutions can be added without needing to rewrite this overview.

## My problem-solving workflow

1. **Understand the problem** — identify inputs, expected output, constraints, and edge cases.
2. **Start with a clear approach** — make sure the reasoning is correct before optimizing.
3. **Look for a better solution** — use relevant properties of the input and known algorithmic patterns.
4. **Analyze complexity** — evaluate time and auxiliary space.
5. **Test carefully** — check examples, boundary cases, and unusual inputs.
6. **Review and document** — keep the solution readable and record useful insights when appropriate.

## Code and complexity

Solutions are primarily written in Python and may follow LeetCode's expected class or function format. Unless noted otherwise, complexity refers to the algorithm being discussed:

- **Time complexity** describes how the work grows with input size.
- **Auxiliary-space complexity** describes the additional memory used, excluding the input where the convention allows.

When multiple approaches are included, the intention is to make the trade-offs clear rather than optimize at the expense of understanding.

## Running solutions locally

Some solutions use the function or class signature required by the original coding platform and therefore do not include a standalone test harness. To run one independently, create a small test script or add sample inputs suited to that solution.

Python 3.9 or newer is recommended for built-in type annotations such as `list[int]`.
